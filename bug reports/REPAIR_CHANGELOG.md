Passing the old seven scripts alone is not used as evidence that a reported defect is fixed.

## Save compatibility and failure semantics

- Save schema remains **4**, accepting existing versions **1–4**. `bagSlots` and `containerSlots` remain canonical. `pendingCook` is ingredient escrow, never a duplicate carried stack. New fields are optional for legacy data.
- New farms receive a generated identity. Existing saves derive a stable seed identity when absent, scoped by their slot's keys; valid old restore points continue to match. New replacements always use a different explicit identity. Historical data without original identity information cannot provide stronger provenance than its retained seeds.
- localStorage provides an atomic write per key. Cooking uses that single-primary boundary. Replacement commits the new primary first; identity checks make stale companion cleanup failures safe. No general cross-key atomicity or browser-storage durability is claimed.
- Invalid history bytes are retained in `<slot>.history.unreadable`; invalid undo bytes in `<slot>.before-restore.unreadable`. A different existing unreadable backup is not overwritten: the operation stops instead. These are recovery bytes for investigation, not an implemented export/import feature. Explicitly replacing/deleting a farm clears its companion recovery data when storage permits.
- Already-lost inputs from old interrupted cooks cannot be inferred or refunded reliably. Past market overpayments are not automatically deducted. Device/site-data deletion remains outside localStorage recovery guarantees. Avoid opening a newly saved pending-cook game in the old buggy HTML, which cannot interpret that reservation.

## Reproduce and verify

From the repository root, with the existing locked Playwright and Chromium setup:

```sh
npm test
npm run test:stability -- --record=independent-recheck
npm run test:stability -- --group=save
```

Other groups: `economy`, `lineage`, `actions`, `town`, `migration`, `activity`. Every context is disposable. The regression runner returns nonzero for any failed expected-behaviour case; it does not label successful bug reproductions as product passes. Baseline evidence records all nine original failures and the additional migration failure. `verification/final.json` contains the tested HTML SHA-256 and final named results. Group JSON files retain staged verification. No real-player saves or credentials are included.

The final `npm test -- --record=final` run passed all eight script processes: the original seven suites plus 29 named PASS / 0 FAIL rows in the stability suite. Do not add the independent report's 83 named checks to these results: those original runners were not supplied. Corrected test-fixture assumptions (such as providing the actual hall return door) are not counted as game bugs. A suspected ordinary HUD click during an activity was blocked by the existing modal; it was not promoted to a new defect. Defensive synthetic stale-input checks cover the transaction guard.
